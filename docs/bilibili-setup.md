# B站官方弹幕接入

更新日期：2026-11-09。本页保留官方open_live接入指南。用户当前官方申请中，已明确改用 [bilive-danmaku方式](sources/bilive-danmaku.md) 的web访客读取固定房间9748572，且禁止登录其B站账号。当前不需要等待官方Key；web配置与验证见 [README](../README.md)。不扫码、不配置SESSDATA、不读取浏览器登录Cookie。官方审批完成后再根据用户指令启用下述官方模式。

## 1. 申请应用与消息权限

进入[B站直播开放平台](https://open-live.bilibili.com/)，按[官方快速开始](https://open-live.bilibili.com/document/849b924b-b421-8586-3e5e-765a72ec3840)完成直播开发者入驻，获取直播接入使用的 Access Key ID / Access Key Secret，并创建应用以获取数字项目 ID。

本项目属于辅助主播的直播工具，可用以下已整理内容填写申请说明；个人/企业身份信息、联系方式及协议由申请人按实际情况填写和提交：

| 项目 | 可使用的说明 |
| --- | --- |
| 应用名称 | BigWhaleLive AI 陪伴直播助手 |
| 应用类型 | 直播工具，具体以当前平台可选类型与审核要求为准 |
| 功能说明 | 接收主播授权直播间的普通文字弹幕，经排队、去重和内容筛选后，由 AI 虚拟主播生成回复并在本地舞台合成语音与字幕。主播可暂停、跳过和关闭语音。 |
| 申请的消息类型 | `LIVE_OPEN_PLATFORM_DM`（普通弹幕）；会话结束通知用于停止已失效的连接 |
| 使用场景 | macOS 本地运行，浏览器竖屏舞台，后续通过 OBS 采集 |
| 数据处理 | 只保留有界的内存队列、去重记录和近期对话；不记录凭据或完整原始弹幕到默认日志，不采集礼物/付费消息玩法 |

需要同时具备开发者资格、应用 ID 和弹幕消息权限。按官方说明，未申请对应消息类型可能建立连接却收不到弹幕；未上架应用还受开发者测试房间等白名单限制。审批时限和当前可接入资格以平台为准，项目代码无法代替平台授权。

主播身份码由主播从[幻星互动](https://play-live.bilibili.com/)的身份码入口获取。身份码、项目 ID 和直播间房间号是不同字段；本接入通过官方应用开启接口确认所属直播间，单独填写房间号不足以鉴权。

## 2. 本地填写配置

只修改本机 `.env`，不把值写入示例、前端、截图或聊天。保留原有 DeepSeek、小鲸固定声线及其他配置。

```dotenv
BILI_MODE=open_live
BILI_APP_ID=填写数字项目ID
BILI_ACCESS_KEY=填写直播开发者AccessKeyID
BILI_ACCESS_SECRET=填写直播开发者AccessKeySecret
BILI_AUTH_CODE=填写主播身份码
```

`BILI_APP_ID` 是正的 int64 范围数字，不是房间号。若暂时没有凭据，保持 `BILI_MODE=off`，仍可使用模拟弹幕。

在项目根目录用主应用环境执行无网络配置自检：

```bash
.venv/bin/python tools/check_bilibili.py
```

命令只输出模式和缺少的键名，不打印值。退出码 2 表示配置不完整或非法；单纯配置项齐全不代表授权成功。

## 3. 验证真实接收

先不要同时启动多个使用同一组配置的接收进程。若主服务已启用 B站接入，先停止主服务再使用独立接收检查；完成后恢复正常启动。默认 `BILI_MODE=off` 的模拟服务不会占用开放平台场次。

```bash
.venv/bin/python tools/check_bilibili.py --listen --seconds 60
```

命令真实调用官方 start、维持两套心跳、连接平台返回的 WSS，统计正常文字弹幕，最后调用 end。最多等待指定秒数，收到3个不同事件ID的有效样本后提前结束，重复推送不能充数。它不调用 LLM 或 TTS，不保存弹幕原文。请在已授权的直播间由观众手动发送至少 3 条文字弹幕；本工具不代替观众发送消息。

输出 `status=connected` 仅表示长连鉴权通过；最终 `received` 至少 3 且没有连接/收尾错误才以退出码 0 结束。未达标退出码 1，需结合 `reason` 和 `error_code` 排查。

## 4. 连接真实主播链路

停止独立接收检查后，用 [README](../README.md) 的正常命令重启单 worker 服务。配置只在启动时读取；更新 `.env` 后必须重启。

1. 刷新控制台，确认平台显示“B站官方弹幕 · 已连接”和正确房间号。
2. 在舞台启用声音并取得播放权，然后开始主播。
3. 从授权直播间发送 3 条不同的真实文字弹幕，确认控制台显示带“B站”的观众消息，且对应 AI 回复实际播放结束。
4. 暂停主播：连接和两套心跳保持，新弹幕被丢弃，不调用模型。恢复后不补播暂停期间的消息。
5. 网络恢复、权限恢复或会话结束后，可在控制台使用“重连弹幕”，或再次开始/恢复主播，触发新一轮有界接入。身份码或密钥已修改时先重启，单纯重连不会重新读取 `.env`。

模拟弹幕入口仍可用于本地排查，平台事件与模拟事件使用不同 ID 命名空间；平台身份使用 `open_id`，避免固定为 0 的旧 `uid` 把所有人算成同一观众。跨房、礼物、付费留言和表情包不在本次普通文字弹幕接入范围。

## 5. 失败与恢复

| 诊断 | 处理 |
| --- | --- |
| 4001 / 4002 / 4008 / 7007 / 8002 | 核对直播开放平台凭据、权限、身份码与项目 ID；鉴权/权限错误不自动重试 |
| 4007 | 核对平台报备的 IP 白名单与当前网络出口，具体以平台配置为准 |
| 5004 / 5011 | 检查应用是否只能连接开发者自己的测试房间及房间授权 |
| `socket_unavailable` / `socket_heartbeat_timeout` | 网络故障最多按 2、4、8 秒重连 3 次并切换官方返回的集群；不会后台无限重连 |
| 7003 | 平台明确场次已失效，才允许在当前重试预算内重建场次 |
| `session_ended` | 平台明确终止消息推送，停止自动连接，等待主播主动重连 |
| start 请求超时 | 不盲目重复开启，避免第一次已在平台成功但响应丢失后创建重复场次；核对平台状态后主动重连 |
| `end_failures` 大于 0 | 场次收尾未确认成功，检查网络及平台状态；不能记为完整生命周期验收通过 |

断线后不使用演示消息冒充 B站数据。普通消息仍受去重、冷却、容量、TTL 和阻止词控制，不保证每条弹幕都获得回复。过期重放消息会被丢弃。连接失败不阻止操作者使用本地模拟输入；控制台独立显示平台失败状态。

## 6. 已核对的官方合同

- [直播开放平台鉴权与错误码](https://open-live.bilibili.com/document/74eec767-e594-7ddd-6aba-257e8317c05d)：直播专用 1.0 签名，精确请求体 MD5 + HMAC-SHA256，无签名串尾部换行。

- [长连协议](https://open-live.bilibili.com/document/657d8e34-f926-a133-16c0-300c1afc6e6b)：大端 16 字节头、鉴权 7/8、心跳 2/3、消息 5；支持同帧多包及版本 2 zlib 递归包。
- [长连命令](https://open-live.bilibili.com/document/f9ce25be-312e-1f4a-85fd-fef21f1637f8)：`LIVE_OPEN_PLATFORM_DM`、`open_id`、`msg_id` 和场次推送结束通知。
