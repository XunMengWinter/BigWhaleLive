## 1. 第一轮交付边界

阶段 1A 交付不需要密钥、网络、模型或直播间的本地演示：预设台词、模拟弹幕、字幕舞台、控制台、暂停和恢复。当前舞台按用户要求使用内置 dsh-pet 大肥鱼透明动画；这是视频立绘，不是 Live2D。阶段 1B 的真实 LLM 与 Edge TTS 已通过联调。1A 通过不代表语音、真实 AI 或完整 MVP 通过。

首版采用 Python 3.11、FastAPI、asyncio、Pydantic 2 和原生 HTML/CSS/JavaScript。暂不引入 Vue、React、数据库或前端开发服务器。Live2D 阶段再添加 PixiJS 6.x 与插件依赖，使用构建工具生成同源静态脚本。具体补丁版本在首次安装验证后锁定，不能将未安装的组合记为兼容性通过。

## 3. 输入、队列与调度

所有输入先转成内部事件：`event_id`、`source`（`local` 或 `bilibili`）、`user_id`、`user`、`text`、`received_at`、`priority`。时间戳用于展示，TTL、超时和排序使用注入的单调时钟；同优先级按接收顺序处理。

1. 校验文本及长度，去除首尾空白，移除控制字符，执行阻止词匹配。匹配采用 Unicode NFKC 和不区分大小写，屏幕仅显示清洗后的文本。
2. 使用来源与事件 ID 去重；已接受的 ID 重复提交时返回原结果。平台无 ID 时使用来源、用户标识、原始消息时间和文本的摘要；不从展示昵称推导真实身份。
3. 本地测试的用户标识按清洗后的昵称派生。容量、TTL、用户冷却及去重上限见运行配置。未入队的事件不占用去重记录或用户冷却。
4. 普通弹幕固定优先级 `10`；自主发言为 `0`，仅在队列为空时现场生成，不占队列。客户端与 LLM 均无权指定优先级。
5. 每次只生成、合成和播放一条台词。普通弹幕不打断当前台词，等待下一轮。暂停和跳过属于操作者控制，可立即取消；礼物等高优先级抢占推迟到后续阶段。
6. 队列满时拒绝新消息，不静默丢弃已接受消息。每次出队前先清除过期项；暂停清空队列。控制台展示队列长度及接受、重复、过期、拒绝、失败计数。

空文本、超长、冷却、阻止词和容量规则均先于 LLM 调用执行。首版使用上述确定性规则筛选，不额外调用一次 LLM 为每条弹幕评分，也不承诺回复每条弹幕。

## 4. 状态与异步一致性

会话状态分为两维，避免“回复中”和“播放中”两套状态相互覆盖：

- `mode`：`paused` 或 `running`。启动默认 `paused`，页面连接本身不启动主播。
- `phase`：`idle`、`generating`、`synthesizing`、`awaiting_playback`、`playing`。

`blocked_reason` 单独表达 `no_renderer`、`audio_blocked` 或 `provider_backoff`，无阻塞时为 `null`。`running` 且无可用播放者时不生成台词、不调用付费 LLM；接受的弹幕仍受 TTL 限制。

| 触发条件 | 状态变化与动作 |
| --- | --- |
| start 或 resume | 幂等设为 running；有播放者时开始调度，自主话题首次等待配置间隔，默认 15 秒 |
| 有未过期弹幕且 idle | 取最早同优先级事件，进入 generating |
| 无弹幕，距上次结束达到自主间隔 | 选择下一话题并进入 generating |
| 台词通过校验 | edge 模式进入 synthesizing；off 模式直接推送字幕发言 |
| 音频或字幕发言准备好 | 推送 utterance.ready，进入 awaiting_playback |
| 当前播放者确认 started | 进入 playing，启动结束计时器 |
| 当前播放者确认 ended | 记入已完成对话，清除当前发言，回到 idle |
| 生成失败或台词不合格 | 发出错误、丢弃本条事件，idle 并等待 5 秒恢复；不重试该事件 |
| TTS 失败 | 本条退为有错误标识的字幕发言；不伪装语音成功 |
| pause | 设 paused，清空队列，取消当前发言并通知舞台停止 |
| skip | 保持 mode，取消当前发言，保留队列；无当前发言时返回 409 |
| 播放者丢失、播放报错或超时 | 取消本条，不重放；标记播放者未就绪，等待重新就绪 |

`start` 和 `resume` 含义相同。paused 转 running 时将自主话题的下次时间设为当前时间加配置间隔；已 running 时重复操作不重置计时。每次发言完成或取消后重新等待自主间隔，队列中的弹幕可立即进入下一轮；模型失败另受 5 秒退避限制。重复暂停且已无活动时不重复取消。退出服务取消全部任务；B站会话按官方生命周期结束。

每个服务进程生成 `instance_id`；每条发言生成 `utterance_id`。暂停、跳过、播放者失效时增加 `epoch`，取消对应任务。所有异步完成回调先校验 instance、epoch 和发言 ID，再修改状态。取消不是仅发送一次任务取消请求：即使旧 HTTP 响应迟到，也不能推送或播放。

操作者控制、所有权变更和任务完成回调通过同一调度器串行修改状态。网络 I/O 不持有状态锁；快照和事件在状态更新后按同一顺序发布。

## 5. 播放者与浏览器行为

同一后端最多一个舞台连接拥有播放权。控制台不申请播放，额外舞台只预览字幕和角色，不播放声音、不发送播放确认。

舞台连接后先握手；off 模式可立即声明就绪，edge 和 qwen_local 模式先通过舞台内“启用声音”操作准备音频。浏览器可能阻止自动播放，必须捕获 `play()` 拒绝并显示操作入口，不能当作播放结束。[MDN 自动播放说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay) 描述了这些限制。

播放权按就绪申请先到先得，不抢占仍存活的播放者；播放者断开或声明未就绪即释放。其他舞台需再次明确申请，不自动播放上一条。OBS 联调时先释放浏览器预览播放权，再通过 OBS 的交互窗口使来源就绪并申请；是否能输出声音以 OBS 实测为准。

每次发言只向播放者提供执行指令，其他连接接收展示状态。收到取消、更换服务实例或 WebSocket 断开时，前端立即停止音频、清除字幕计时器和旧动作。重连使用全量快照，不恢复旧音频。

## 6. 台词、记忆与失败处理

LLM 适配先采用非流式 Chat Completions 兼容接口。要求返回 `text`、`emotion`、`action`，不使用工具调用；DeepSeek 官方接口显式禁用思考模式并开启 JSON 对象输出；具体请求和返回校验见协议。真实模式失败直接显示错误，不能自动改用预设台词并仍声称是真实 AI。

短期记忆只保留最近 20 次已完成发言及对应观众输入。中断、未播放或失败内容不记成说过。自主话题按本地列表轮换，最近自主话题保存在内存；暂不增加独立摘要模型调用。弹幕回复结束后继续下一话题或近期话题，避免每次自我介绍。

用户最新决定停用课程与新闻，但随后要求把知识库重建为网友二创玩梗素材。`knowledge/`现为103条「海底办公室·AI江湖」虚构条目（全部 `fictional`、来源为 `fiction`），真实LLM按当前弹幕做有界检索，命中才在user JSON的`reference_material`中注入；条目带虚构note、不产生来源URL，无关聊天不强制注入。课程与新闻仍不加载，`knowledge/archive-winter/`不读取。知识文件仍不挂载HTTP。玩梗只玩性格梗，不影射真实事件、价格、人物或黑料，不当新闻转述，规则见 [摸鱼搭子](companion-mode.md)。

Agent在出队时为本回合生成不可变ScenePlan，通过LLM内部generate的可选scene上下文传入；生成和合成不改变已提交处境。唯一播放者的合法started提交，合法ended递减后续回合，归零回到摸鱼；暂停、跳过、失去播放者和关闭取消时重置。模型不能修改该状态。会话记忆保留实际emotion/action，仍仅记录已播放完成的回合。前端继续使用既有动画和情绪展示，不改布局、素材或播放器。

输入和输出都经过阻止词检查；命中则丢弃并报告 `content_blocked`。清单默认允许为空以便本地开发，正式直播前必须审阅人设、话题及清单并人工验证，不能将该简单过滤描述为完整内容审核系统。模型输出仅映射到白名单动作，不能触发代码或文件操作。

Edge TTS 是联网服务，[上游说明](https://github.com/rany2/edge-tts) 明确其使用在线语音合成；无密钥演示不等于离线语音。off 模式不请求 TTS，字幕时长按 `clamp(文本字符数 × 80, 2000, 10000)` 毫秒计算，并按同一 started/ended 协议确认。

用户当前选定本地小鲸 v1。qwen_local 通过独立 Python 环境的常驻子进程运行 Qwen3-TTS Base，始终使用 `assets/voices/xiaojing-v1/` 内经过 SHA-256 校验的原创参考音频与文本。模型版本固定，权重预装在忽略的缓存目录；运行时启用离线模式，不自动下载或回退 Edge。生成在子进程执行，不阻塞 HTTP/WebSocket 心跳；取消、超时或协议错误时终止工作进程，下一轮重新加载，不接收迟到音频。常规发言复用模型和参考编码，关闭服务回收进程。单条本地合成总时限默认 90 秒，输出最多 42 秒、5 MiB，仍采用成功后原子发布的 MP3 播放协议。舞台的所有非 off 模式均须通过点击启用声音后就绪。

SpeechPlayer 复用一个实际音频元素。启用声音按钮在用户点击内播放一段本地静音 WAV，取得该元素的播放就绪状态；真实 MP3 的 playing/ended 事件才触发语音确认。取消时先移除监听器、暂停并清除音源，迟到的 play Promise 不会重新启动旧音频。

公开诊断只保存调用计数、最近状态及最多 20 条发言耗时，不包含凭证或观众文本。ready_ms 和 started_ms 从后端接收弹幕时起算，包含排队等待；自主发言从开始生成时起算。

失败事件以短错误码展示；默认日志仅记录 ID、耗时、计数和错误码，不记录凭证或完整弹幕。音频合成先写临时文件，成功后原子改名；清理任务保留当前发言音频，删除过期及超量的已结束资源，具体参数见运行配置。

官方接入需要开发者与应用资格、密钥、主播身份码和相应消息权限，单独房间号不足以建立授权会话。按[官方应用 API](https://open-live.bilibili.com/document/eba8e2e1-847d-e908-2e5c-7a1ec7d9266f) 实现开启、应用心跳和结束，再按[官方接入说明](https://open-live.bilibili.com/document/849b924b-b421-8586-3e5e-765a72ec3840) 对接消息长连；应用心跳与长连保活分开管理，签名及帧协议在 S3-1 依据当时官方合同复核。授权条件未具备时将真实联调标记为待外部条件，不阻塞阶段 1、2。

阶段 3 适配器生命周期约定：

1. 仅 open_live 模式在服务启动时开启官方应用会话，保存返回的场次标识和长连参数；paused 时保持连接，但拒绝入队，不触发模型。
2. 应用心跳和长连保活按各自官方频率调度；本地舞台心跳与它们无关。原始平台消息先映射为内部事件，再复用筛选和队列规则。
3. 连接失败在一轮尝试中按 2、4、8 秒最多重连 3 次，单次 HTTP 与 WS 鉴权时限均为 10 秒；权限或鉴权错误不自动重试。之后置 bili_status=error，不后台无限循环；操作者再次 start/resume 可触发新一轮连接尝试。错误清理期间的重复点击合并为一次待重连请求。
4. 场次仍有效时只恢复消息连接并轮换官方返回的 WSS 集群，复用原鉴权体，不重复开启应用；应用 HTTP 心跳在 WS 重连等待期间继续。仅明确收到 7003 才允许自动重建已失效场次；明确的 INTERACTION_END 则等待操作者重新连接。start 响应丢失时不盲目重发，避免创建重复场次。
5. 退出服务时最佳努力调用结束接口，时限 5 秒；记录 end_failures 后关闭客户端。已经开始的有界 end 任务由 shutdown 等待，不因连接任务取消而丢失。测试覆盖正常关闭、半断连、服务端拒绝、收尾超时及关闭竞态。

官方合同与申请指南见 [B站接入说明](bilibili-setup.md)。当前实现使用直播专用 1.0 签名，精确请求体计算 MD5，排序 x-bili-* 请求头并用 Secret 做 HMAC-SHA256；不加签名串末尾换行，不打印鉴权体。WS 首包发送官方 auth_body，收到 code=0 的操作 8 回复后才标为 connected；仅打开 TCP/WS 传输不等于接入成功。默认 TLS 校验保持启用，WSS 限于官方域名。

应用 HTTP 心跳与 WS 操作 2 心跳分别每 20 秒维护，WS 操作 3 回复超过 40 秒未收到则失败。二进制解析使用大端16字节头，支持同帧多个协议包及 zlib 递归包，边界见运行配置。错误业务消息只计 invalid，不执行代码或请求其携带的URL；未知命令和非普通文字弹幕不接入回复队列。

平台身份依据 open_id 派生有界用户标识，不能使用已固定为0的uid或昵称作为唯一身份。事件ID按房间号与msg_id派生；缺少消息ID时使用房间、用户、原始时间戳与清洗后的文本摘要。通过检查的事件调用与模拟输入相同的 `_accept`，共享容量、去重、冷却、阻止词和固定优先级10。时间戳过旧的重放事件在平台入口丢弃，等待队列仍按本机接收时间执行TTL。

暂停期间观察到而拒绝的事件另保留不含文本的有界ID记录（沿用10分钟/1000条限制），防止恢复后重连推送同一消息再入队；不改变本地HTTP拒绝项不消耗去重记录的合同。

公共状态只含平台模式、连接状态、已验证的房间号及无内容诊断；accepted 的平台消息通过 `danmaku.received` 事件进入控制台，仍用文本节点渲染。HTTP模拟入口不能指定source/user_id/priority，不能伪装平台消息。前端采用有序WS快照渲染状态，避免迟到的HTTP控制响应覆盖已恢复的连接。

## 8. 本地运行边界

默认服务仅监听 `127.0.0.1:8765`，静态资源与接口同源。应用工厂可为隔离验收指定另一个本地端口，Host 和 Origin 也只允许该实例自己的端口；不接受通配来源。状态修改要求 JSON；校验存在的 Origin 和 Host，仅允许本机服务来源，不开放通配 CORS。WebSocket 校验本机 Origin。首版无远程管理认证，因此不作为公网或局域网服务部署。

静态路由只挂载 `static/`、`models/`、`vendor/` 等明确目录，不能挂载仓库根目录。音频仅允许服务生成的 UUID 文件名，拒绝路径穿越；`.env` 和平台凭证绝不通过静态路由返回。
