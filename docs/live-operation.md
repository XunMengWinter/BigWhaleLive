2026-11-09，用户明确要求“直接让大肥鱼接管直播”，并提供推流配置。已在当日12:20（Asia/Shanghai）切换为独立 `BigWhaleLive` 配置/场景集合，当前使用8766后端、B站9748572游客弹幕、DeepSeek和小鲸v1固定声线。不是本地测试配置 `BigWhaleLocal`。

## 当前操作

- [直播间](https://live.bilibili.com/9748572)：公开观看画面和声音。
- [直播控制台](http://127.0.0.1:8766/control)：暂停、恢复、跳过。暂停主播会立即停止当前语音和后续生成，但OBS继续发送待机画面。
- 需要结束直播时，在 `BigWhaleLive` OBS窗口点击「停止直播」。不要误操作其他OBS窗口。该配置也有 `Ctrl+Option+Shift+F8` 停止推流快捷键。
- 普通浏览器预览不要申请播放权；唯一播放者应为OBS来源「大肥鱼·竖屏与声音」。

- 当前为摸鱼搭子模式 + 「海底办公室·AI江湖」二创玩梗素材库，`diagnostics.knowledge`为ready对象；三种处境见`diagnostics.companion`。发送“老板来了”“开饭了”“别偷懒”可触发角色反应；提到 DeepSeek、Claude、大模型八卦时检索虚构梗接话，不当事实或新闻。规则见 [摸鱼搭子](companion-mode.md) 与 [素材库](../knowledge/README.md)。

旧8765后端已停止，避免重复读取弹幕和驻留两套Qwen模型；旧横屏OBS已停止推流，原有场景和凭据没有重写。不要继续使用8765控制台管理当前直播。

## 重启步骤

```bash
./tools/start_live.command
```

也可以双击此文件。需要保留该终端运行；它不安装开机自启，关闭终端或Ctrl+C将停止后端。8766已经运行时不要重复启动。启动器沿用私有 `.env`；本机已配置为未登录的web游客读取，不扫码、不读取登录Cookie。

在OBS中选择配置文件和场景集合 `BigWhaleLive`，场景「大肥鱼·直播」。确认舞台已取得播放权，在独立控制台开始主播，再按需要点击OBS「开始直播」。启动器本身不点击推流或开始主播，避免误开播。若只做测试，按 [本地采集](obs-local.md) 使用 `BigWhaleLocal`；两种后端共用8766端口，不能同时运行。

## 已部署参数与凭据

- 画布、输出、来源：1080×1920，30 FPS，Apple H.264硬件编码，视频4500kbps、音频160kbps。
- 只有浏览器来源音频进入推流，监控关闭；不采集桌面和麦克风。页面显示AI身份和素材署名。
- 推流凭据仅在本机OBS `BigWhaleLive` 的私有 `service.json` 和项目忽略的 `runtime/obs-live/` 中，权限0600；不写入文档、脚本、前端、Git或公开状态接口。原有OBS配置没有被覆盖。
- 自动重连间隔2秒，最多10次；持续拒绝时先暂停主播，在OBS检查错误，不循环登录或重新获取账号会话。
- 服务是单进程本机运行，机器、终端和OBS需保持运行。停止输出、程序崩溃或机器休眠不会由本轮自动恢复机制保证重新开播。
